# 編集メモの運用

既存の国内更新（JST 06:10 / 12:10 / 18:10ごろ）で、収集後に `npm run editorial:update` を実行する。新しい記事から一次情報の本文を確認し、短い段落を1件抜粋する。推測による解説・日付・申込条件の補完やAI APIの利用は行わない。「一次情報から抜粋・自動更新」と確認日時、出典リンクを表示する。

- `config/editorial.mjs` の許可済みホスト・記事パス・本文構造だけを対象にする。追加時は実際の本文・掲載日を確認し、抽出テストを追加する。
- HTTPSの本文を毎回取得し、見出しと掲載日を収集済み記事と照合する。最大6候補・全体45秒・各8秒。リダイレクト先は同じ記事に限定し、接続時のDNSも検証する。
- 他団体の転載と判別できる案内、終了の告知、本文が画像・表のみの案内、抽出構造や日付が一致しない記事は採用しない。短い段落（35〜160字）を引用として表示し、切れた文章を補完しない。
- 確認結果を `.state/editorial.json` に保存する。本文全体の転載は保存せず、本文ハッシュ・採用/除外理由・実際の確認日時を記録する。公開ビルドはネットワーク不要で、この記録だけを使用する。
- 期限は「一次情報の掲載日から7日」と「本文確認から24時間」の早い方。同じ記事を再確認しても掲載日からの期限は延ばさない。取得に失敗した記事は再利用せず、確認できる次の候補へ進む。
- 新しい候補がない・全候補を確認できない場合は空のメモを保存し、欄を消す。更新処理自体が止まっても、期限切れはブラウザーの初回表示・再表示・タイマーで非表示にする。
- 期限を確認できないJavaScript無効時はメモを表示しない。ニュース本文・一覧は引き続き利用できる。
- push競合時も確認結果を退避・復元し、再ビルドする。再取得や確認日時の付け替えは行わない。
- 検証は `npm test` → `npm run editorial:update` → `npm run build` → `npm run verify`。再取得を伴わない通常CIは、保存済み記録を使う。取得失敗時はActionsの警告と記録の `checks` を確認する。

# 掲載品質

関連語の取りこぼし対策として字幕用スマートグラス・字幕タブレット・文字通訳・耳マーク・ヒアリングループ・磁気ループ・筆談カフェ・聾者を選別語彙と探索に含める。一般の字幕や鑑賞サポートという表現だけでは聴覚との関係を推測しない。確認済みの聴覚分野専用の直接フィード7件は、題名が一般的なサービスのお知らせも最低点5で拾う。自治体・一般媒体全体の足切りは緩めず、明確な対象外・仮ページ・市場広告の除外、日付・重複・掲載上限は維持する。収集時に除外理由・低得点の例を点検し、取りこぼしと、アーカイブ移動・重複統合・取得失敗を区別する。

収集時とビルド時に、工事中等の仮ページ、関連文脈のない一般記事、市場レポート告知を除外する。承認済みの公式・専門フィードでは地域団体の日常のお知らせを残す。タイトルから情報源名の末尾表記を整理し、発生日や地域が異なる記事は重複扱いしない。

Worldは audífonos の娯楽用ヘッドホン記事を、補聴器の文脈と区別する。Librasの誤訳は翻訳キャッシュの再利用対象から外し、既存の不足分翻訳経路で再判定する。保存済み記事に残る該当誤訳は公開スナップショットから外す。翻訳API・モデル・定期実行頻度・課金方針は変えない。

`articles*.json` の `publicationReview` に、ビルド時に除外した記事ID・理由を記録する。元の収集日時と収集時のqualityレポートは保持する。アーカイブ原本とGit履歴は書き換えない。掲載後の訂正は元情報・記事IDを照合して行う。

ニュースの `newsContext` は記事の種類（announcement=開催案内、report=開催報告）。参加受付中という保証ではない。明確な表現のみ判定し、日付や「報告会」という演題だけでは決めない。要約が短く判断できない場合は元記事を読み、`config/news-context.mjs` に根拠URL・確認日・短い要旨を残す。公開日や元の見出しは変更しない。
