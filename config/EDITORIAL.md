# 編集メモの運用

`config/editorial.mjs` に、出典本文を確認した短い編集メモを置く。表示は最大2件、通常1件。ニュース収集処理が編集文を自動生成することはない。

- 見出しは短く、本文は2文程度。発表・要望と、施行・決定を区別する。
- `sourceUrl` は本文を確認した HTTPS の一次情報へ。`sourceName` も明示する。
- `reviewedAt` は実際の確認日、`expiresAt` は掲載終了日時。日本時間のオフセットを付ける。原則7日、最長14日。
- 更新するときは出典を再確認し、確認日と期限を更新する。期限の自動延長はしない。
- 期限切れ・未来日・不正な出典URLのメモはビルド時に表示しない。キャッシュ済みページもJavaScriptが有効なら期限到達・再表示時に隠れる。
- メモがない日は欄ごと消え、公式・専門団体の新着と最新ニュースを表示する。
- `npm test` → `npm run build` → `npm run verify` で確認。config変更は既存の国内キュレーション・公開ワークフローを起動する。

# 掲載品質

収集時とビルド時に、工事中等の仮ページ、関連文脈のない一般記事、市場レポート告知を除外する。承認済みの公式・専門フィードでは地域団体の日常のお知らせを残す。タイトルから情報源名の末尾表記を整理し、発生日や地域が異なる記事は重複扱いしない。

Worldは audífonos の娯楽用ヘッドホン記事を、補聴器の文脈と区別する。Librasの誤訳は翻訳キャッシュの再利用対象から外し、既存の不足分翻訳経路で再判定する。保存済み記事に残る該当誤訳は公開スナップショットから外す。翻訳API・モデル・定期実行頻度・課金方針は変えない。

`articles*.json` の `publicationReview` に、ビルド時に除外した記事ID・理由を記録する。元の収集日時と収集時のqualityレポートは保持する。アーカイブ原本とGit履歴は書き換えない。掲載後の訂正は元情報・記事IDを照合して行う。
