# 管理画面のログイン維持

2026-10-23のユーザー指定により、通常のログインを操作間隔で失効させない。
従来は無操作2時間・ログイン後12時間・ブラウザー終了で失効していた。

`deafnavi_admin_login` はランダム256ビットのホスト限定Cookie。
Secure / HttpOnly / SameSite=Lax、全管理ルートと非公開読みものプレビューで利用するためPath=/。
ブラウザーの上限に合わせて400日、認証付き利用時に1日単位で延長する。
Cookie削除、400日以上の未利用、ログアウト、パスワード変更、権限変更・停止時は再ログインが必要。
パスワードを変更した端末だけは新しいログイン保持情報を発行する。

公開root外の既存directory.sqliteに `admin_login_sessions` を追加する。
保存するのはトークンのSHA-256、ユーザーID/認証version、CSRF、作成・失効日時。
元トークンをDB・ログ・監査ログへ保存しない。
毎リクエストで有効なユーザー・version・失効日時を照合する。
短いPHPセッションの残存や複製だけでは、ログアウト済みの保持情報を再使用できない。
フォームのCSRFも復元するため、PHPセッションのGC後も開いていた編集フォームを送信できる。
公開問い合わせの匿名セッションは従来の2時間GCを維持し、長期Cookieを作らない。

初回利用時に追加だけのSQLを適用する。適用前は既存CLIの整合バックアップを取得する。
既存のusers/掲載情報/投稿/通知設定は変更しない。有効期間内の旧ログインは次の利用時に移行し、既に期限切れの旧ログインは復活させない。
ロールバックは既定のリリース切戻し。追加テーブルは旧コードから無視され、削除やDB全体の復元は不要。
復旧時は従来の短時間ログイン仕様に戻る。秘密のCookieやトークンを検証記録へ出力しない。

検証: `node test/admin-session.integration.mjs`。時間経過、PHPファイル消失、ブラウザー再開、期限更新、ログアウト後のリプレイ拒否、パスワード/権限/停止時の失効、CSRF、旧セッション移行を合成データで確認する。
