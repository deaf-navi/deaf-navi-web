# Worldの地域確認を続ける条件

地域未確認のゼロ化を運営目標にしない。地域未確認は公開保留とは別であり、未確認件数の削減だけで掲載品質を評価しない。

- 制度の管轄、利用できるサービスの提供先、催事の会場など、地域が利用判断に必要なものと誤分類の疑いを優先する。
- 原文と公式情報の対象・固有名詞・時点を照合する。媒体所在地、人物の出身、所属機関、同名の別記事だけでは記事の対象地域を決めない。
- 一般解説や複数地域の話題には単一地域を無理に付けない。本文確認済みの地域不問と、本文未取得を同じ確度として扱わない。
- 新しい原文、公式発表、訂正などが得られなければ未確認で停止する。同じ検索や既知の取得制限への再試行を定期作業にしない。個別の再開条件は調査台帳へ残す。
- 比喩やヘルプ記事の掲載適否は関連性の問題として別に検討する。地理的根拠がないことだけを理由に除外しない。
- 配信ID・日時・原文が変わり確認記録との照合が失敗した場合、以前の確認を無条件に流用しない。旧記録を保持して未確認に戻す。集計の比較時には元データの時点も示す。

2026-10-30の追加確認8件・原文待ち12件の調査では、20件とも新たな地域確定に至らず未確認を維持した。個別記録・実モデルの作業結果は実行チャットの成果物を参照する。地域の公開スキーマは変更しない。

品質集計は `node scripts/report-publication-quality.mjs` で最新の掲載データから作る。`.state/publication-quality-report.json` はWebの公開rootへ配置しない。公開時に既存の非公開データディレクトリへ配置する。集計が未配置・24時間超なら管理画面の未確認・古い集計の表示を維持する。新しい高頻度巡回や有料APIは追加しない。

`.state/publication-review-*.json` と `config/world-location-source-reviews.json` は、公開原文由来の掲載判断・修正の再生成用ソースで、公開Gitリポジトリにも保存される。問い合わせ、非公開取材、認証、アクセスログ、個人の投稿内容を記録しない。調査の生ログ・取得本文全文・CLIログはリポジトリとWeb成果物へ含めない。
